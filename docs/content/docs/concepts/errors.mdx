---
title: Error Handling
description: Sentinel errors for all Keysmith operations.
---

Keysmith defines sentinel errors in the root `keysmith` package. Use `errors.Is` to match them.

## Sentinel errors

| Error | Returned when |
| ----- | ------------- |
| `ErrInvalidKey` | `ValidateKey` gets a key that matches no current key and no key in an open rotation grace window, or a malformed one |
| `ErrKeyInactive` | `ValidateKey` gets a key that is revoked, suspended or otherwise not active |
| `ErrKeyExpired` | `ValidateKey` gets a key past its expiry |
| `ErrRateLimited` | `ValidateKey` finds the key over its policy's rate limit (only with a `RateLimiter` configured) |
| `ErrKeyNotFound` | A lookup by key ID finds nothing |
| `ErrKeyConflict` | A version-checked key update lost a race with another writer |
| `ErrInvalidStateTransition` | The requested state change isn't allowed, such as reactivating a revoked key |
| `ErrPolicyNotFound` | No policy matches the given ID |
| `ErrPolicyNameTaken` | A policy with that name already exists in the tenant |
| `ErrPolicyInUse` | You tried to delete a policy that keys which aren't revoked still use |
| `ErrScopeNotFound` | A scope you named doesn't exist in the tenant (create scopes before keys carry them) |
| `ErrScopeNameTaken` | A scope with that name already exists in the tenant |
| `ErrScopeHasChildren` | You tried to delete a scope other scopes name as their parent |
| `ErrScopeAllowedByPolicy` | You tried to delete a scope a policy still allows |
| `ErrScopeNotAllowed` | `CreateKey` or `AssignScopes` named a scope the key's policy doesn't allow |
| `ErrKeyLifetimeExceeded` | `CreateKey` got an expiry beyond the policy's `MaxKeyLifetime` |
| `ErrRotationNotFound` | No rotation record matches |

Some sentinels are declared but never returned by the engine today: `ErrKeyRevoked` and `ErrKeySuspended` (a revoked or suspended key gives you `ErrKeyInactive`), and `ErrQuotaExceeded`, `ErrIPNotAllowed` and `ErrOriginNotAllowed`, because quotas, IP allowlists and origin allowlists aren't enforced yet. See [Policies](/docs/subsystems/policies).

## Usage

```go
import "errors"

vr, err := eng.ValidateKey(ctx, rawKey)
if err != nil {
    switch {
    case errors.Is(err, keysmith.ErrInvalidKey):
        // Unknown key: return 401
    case errors.Is(err, keysmith.ErrKeyInactive):
        // Revoked or suspended: return 401 (or 403 if you prefer)
    case errors.Is(err, keysmith.ErrKeyExpired):
        // Expired: the middleware returns 403
    case errors.Is(err, keysmith.ErrRateLimited):
        // Rate limited: return 429
    default:
        // Store error: return 500
    }
}
```

The `middleware.APIKeyAuth` middleware answers `ErrRateLimited` with 429 and `ErrKeyExpired` with 403. Everything else, including `ErrKeyInactive` for a revoked or suspended key, gets 401. (It also maps `ErrKeyRevoked` and `ErrKeySuspended` to 403, but since the engine never returns those, a revoked key gets 401.)

## Policy errors

Policy limits surface as their own sentinels, not as one wrapped "policy violation" error: `ErrRateLimited` on validation, and `ErrKeyLifetimeExceeded` or `ErrScopeNotAllowed` on key creation and scope assignment.
