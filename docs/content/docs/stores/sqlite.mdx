---
title: SQLite Store
description: Lightweight SQLite store for development, testing, and single-node deployments.
---

The `store/sqlite` package implements Keysmith's `store.Store` interface using the grove ORM with the SQLite driver. It requires no external database process, making it ideal for development, integration tests, and single-node deployments.

## Usage

```go
import (
    "github.com/xraph/grove"
    "github.com/xraph/grove/drivers/sqlitedriver"
    "github.com/xraph/keysmith/store/sqlite"
)

sdb := sqlitedriver.New()
if err := sdb.Open(ctx, sqlite.DSN("keysmith.db")); err != nil {
    log.Fatal(err)
}
db, err := grove.Open(sdb)
if err != nil {
    log.Fatal(err)
}

s := sqlite.New(db)
if err := s.Migrate(ctx); err != nil {
    log.Fatal(err)
}

eng, err := keysmith.NewEngine(keysmith.WithStore(s))
```

For tests, point it at a file under `t.TempDir()`. Don't use `":memory:"`: every pooled connection opens its own empty in-memory database, so the tables `Migrate` creates on one connection are missing on the next.

## Connection settings

Always open the database with `sqlite.DSN(path)`. It adds three settings to the DSN, and modernc's sqlite driver applies them to every connection the pool opens. If your path already sets one of them, your value wins and `DSN` adds only the missing ones:

| Setting | Why |
| ------- | --- |
| `_pragma=busy_timeout(5000)` | A write waits up to 5 seconds for another connection's write lock. `ValidateKey` writes the key's last-used time in the background, so the next write often finds the lock taken. Without a timeout it fails at once with `SQLITE_BUSY`. |
| `_pragma=foreign_keys(1)` | `ON DELETE CASCADE` runs on every connection. Deleting a key takes its scope links, usage and rotation rows with it, and deleting a scope takes its links. |
| `_txlock=immediate` | Transactions take the write lock at `BEGIN`. SQLite doesn't wait when a transaction that has already read tries to write, and `AssignToKey` reads first. Read-only transactions still begin deferred. |

grove's driver turns foreign keys on for one connection only and sets no busy timeout, and `sqlite.New` takes a `*grove.DB` it didn't open, so the store can't fix this after the fact. If you open the database some other way, from a grove extension's config for example, put the three parameters on that DSN yourself. The Forge extension logs a warning at startup when the busy timeout is missing:

```
keysmith.db?_pragma=busy_timeout(5000)&_pragma=foreign_keys(1)&_txlock=immediate
```

## Migrations

The store uses the grove migration orchestrator with programmatic migrations. Run them on startup:

```go
if err := s.Migrate(ctx); err != nil {
    log.Fatal(err)
}
```

This creates six tables:

| Table | Description |
| ----- | ----------- |
| `keysmith_keys` | API keys with hash, state, and metadata |
| `keysmith_policies` | Policy definitions |
| `keysmith_scopes` | Scope definitions |
| `keysmith_key_scopes` | Key-scope junction table |
| `keysmith_usage` | Per-request usage records |
| `keysmith_rotations` | Rotation history records |

Migrations are idempotent and safe to run on every startup.

## Internals

| Aspect | Detail |
|--------|--------|
| Driver | grove ORM + sqlitedriver |
| Migrations | grove orchestrator with programmatic migrations |
| Transactions | `AssignToKey`, `RemoveFromKey` and `RecordBatch` each run in one SQLite transaction, begun `IMMEDIATE` with the DSN above. Nothing else does. |
| Concurrency | Multiple readers, single writer (WAL mode). Writers queue on the busy timeout. |
| Subsystems | keys, policies, scopes, usages, rotations |

## Health checks

```go
if err := s.Ping(ctx); err != nil {
    log.Fatal("database unreachable:", err)
}
```
