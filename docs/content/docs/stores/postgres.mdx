title: PostgreSQL Store
description: PostgreSQL backend on Grove's pgdriver.

The PostgreSQL store provides a full `store.Store` implementation on Grove's `pgdriver`. It takes a `*pgdriver.PgDB`, not a `*grove.DB`, and its schema SQL is compiled into the package as Go strings.

## Setup

### From a DSN

```go
import "github.com/xraph/keysmith/store/postgres"

pgStore, err := postgres.NewFromDSN(ctx, "postgres://user:pass@localhost:5432/mydb")
if err != nil {
    log.Fatal(err)
}
defer pgStore.Close()
```

### From an existing grove.DB

If your application already manages a `grove.DB` connection (e.g. via the Grove extension), pass the unwrapped pgdriver instance. This is what the Forge extension does:

```go
import (
    "github.com/xraph/grove"
    "github.com/xraph/grove/drivers/pgdriver"
    "github.com/xraph/keysmith/store/postgres"
)

drv := pgdriver.New()
if err := drv.Open(ctx, "postgres://user:pass@localhost:5432/mydb"); err != nil {
    log.Fatal(err)
}
db, err := grove.Open(drv)
if err != nil {
    log.Fatal(err)
}

pgStore := postgres.New(pgdriver.Unwrap(db))
```

## Migrations

Run `Migrate` on startup:

```go
if err := pgStore.Migrate(ctx); err != nil {
    log.Fatal(err)
}
```

`Migrate` runs the grove migration group `postgres.Migrations` through grove's orchestrator. It takes grove's migration lock first (a Postgres advisory lock), applies whatever `grove_migrations` doesn't record yet, and writes each record in the same transaction as the migration's statements. When several nodes start together against one database they take turns: the first applies the schema, and the rest find nothing left to do. You can call it on every start.

`Migrate` needs a direct connection, or one through a pooler in session mode. Grove's lock is a session-level advisory lock, and behind transaction pooling (PgBouncer with `pool_mode = transaction`, or the pooled endpoints Neon and Supabase give you) the lock and the unlock can land on different server sessions. The lock then leaks, and every other node's `Migrate` waits five minutes for it and fails. If your app only reaches Postgres through a transaction pooler, set `disable_migrate` and run `postgres.Migrations` over a direct DSN.

This creates six tables, plus grove's own `grove_migrations` (which versions have run) and `grove_migration_locks` (who holds the lock) if they aren't there yet:

| Table | Description |
| ----- | ----------- |
| `keysmith_keys` | API keys with hash, state, and metadata |
| `keysmith_policies` | Policy definitions |
| `keysmith_scopes` | Scope definitions |
| `keysmith_key_scopes` | Key-scope junction table |
| `keysmith_usage` | Per-request usage records |
| `keysmith_rotations` | Rotation history records |

Each migration is a Go file in `store/postgres` named for its version, such as `20240101000001_create_keys.go`, and registers itself with grove's `Group.Add`. The statements are raw SQL run through `db.Exec`. Grove's Postgres schema builders could express them, but raw SQL keeps the statements keysmith has always shipped byte for byte, `IF NOT EXISTS` guards included, and those guards are what let the group run safely over a schema an older keysmith built.

### Running migrations centrally

If your app runs all its migrations in one place, register `postgres.Migrations` with that orchestrator next to your own groups, and turn the extension's run off with `WithDisableMigrate()` (or `disable_migrate: true`). Leaving both on works too. Both take the same lock, and whichever runs second finds nothing to apply.

## Upgrading to v1.9

The first `Migrate` on v1.9 creates `grove_migrations` and `grove_migration_locks` if they aren't there and records nine rows under the group `keysmith`. After that it never reruns a recorded step.

Up to v1.8.x, `Migrate` ran every statement on every start with no lock and no record, so a database those versions built has no keysmith rows yet, and the first run executes the whole group once. Every step is safe on a schema that's already there: `CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`, `DROP TABLE IF EXISTS`, and an `UPDATE` whose `WHERE` only matches rotations with no old hint and a grace window still open. That `UPDATE` closes the windows of rotations recorded by v1.6 or older, as it used to on every start, and now it runs once. The rest of your tables and rows stay as they are. If you already ran `postgres.Migrations` through your own grove orchestrator, every version is recorded and nothing runs again.

Before you roll it out:

- The lock is advisory key 1, and `Migrate` waits up to five minutes for it. Every grove migrator on that database shares it, authsome's included, so if two start at once, one waits for the other.
- Roll every node to v1.9 before you count on the lock. A node still on v1.8.x runs the old statements unlocked and can still collide with the rest.
- A test that drops something and calls `Migrate` to put it back has to delete that version from `grove_migrations` first, because `Migrate` no longer reruns a recorded step.
- Re-pinning keysmith v1.9.0 also pulls in forge v1.13.2, grove v1.10.1 and go-utils v1.5.0. In forge, nested router groups now inherit `WithGroupMiddleware` from the group above them, and logs go out over OTLP when an endpoint is set. Grove's sqlitedriver turns foreign keys on for every pooled connection, not only the one a pragma ran on.

## Health checks

```go
if err := pgStore.Ping(ctx); err != nil {
    log.Fatal("database unreachable:", err)
}
```

## Usage with the engine

```go
eng, err := keysmith.NewEngine(keysmith.WithStore(pgStore))
```

## Schema overview

### keysmith_keys

```sql
CREATE TABLE keysmith_keys (
    id              TEXT PRIMARY KEY,
    tenant_id       TEXT NOT NULL,
    app_id          TEXT NOT NULL,
    name            TEXT NOT NULL,
    description     TEXT,
    prefix          TEXT NOT NULL,
    hint            TEXT NOT NULL,
    key_hash        TEXT NOT NULL UNIQUE,
    environment     TEXT NOT NULL DEFAULT 'live',
    state           TEXT NOT NULL DEFAULT 'active',
    policy_id       TEXT,
    metadata        JSONB NOT NULL DEFAULT '{}',
    created_by      TEXT,
    expires_at      TIMESTAMPTZ,
    last_used_at    TIMESTAMPTZ,
    rotated_at      TIMESTAMPTZ,
    revoked_at      TIMESTAMPTZ,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_keysmith_keys_tenant ON keysmith_keys (tenant_id);
CREATE INDEX idx_keysmith_keys_hash ON keysmith_keys (key_hash);
CREATE INDEX idx_keysmith_keys_state ON keysmith_keys (tenant_id, state);
CREATE INDEX idx_keysmith_keys_env ON keysmith_keys (tenant_id, environment);
CREATE INDEX idx_keysmith_keys_expires ON keysmith_keys (expires_at) WHERE expires_at IS NOT NULL;
CREATE INDEX idx_keysmith_keys_policy ON keysmith_keys (policy_id) WHERE policy_id IS NOT NULL;
```
