The engine traces its own work, and when you give it a metrics sink it records six metrics. In a Forge app you don't have to do anything. Forge installs the tracer provider the engine uses, and the extension hands the engine `app.Metrics()`, so the series show up on `/_/metrics` next to forge's own.

## Turn it on

With the Forge extension it's already on. To send the metrics somewhere else, or nowhere, override the option the extension sets. Yours is applied after it:

```go
import (
    "github.com/xraph/keysmith"
    "github.com/xraph/keysmith/extension"
)

ext := extension.New(
    extension.WithEngineOptions(keysmith.WithMetrics(nil)), // no metrics
)
```

Without Forge, pass any `github.com/xraph/go-utils/metrics` sink:

```go
eng, err := keysmith.NewEngine(
    keysmith.WithStore(store),
    keysmith.WithMetrics(m),
)
```

Spans go to the global OpenTelemetry tracer provider. Outside Forge, set one with `otel.SetTracerProvider`. Until you do, a span costs next to nothing. An engine built without `WithMetrics` records no metrics at all.

Forge and Grove already cover the layers around Keysmith. Forge opens a server span for every route and records the HTTP metrics, and Grove records a `db.client` span and `db_client_operation_duration_seconds` for every query. Keysmith doesn't measure either again. Its spans sit between the two: under the route's span when a request triggered the work, and above the query spans for the reads and writes it makes.

## Spans

Every span is `SpanKindInternal`, from the tracer `github.com/xraph/keysmith`.

| Span | Started by | Attributes |
| --- | --- | --- |
| `validate key` | `ValidateKey`, under your span | `keysmith.result`, `keysmith.validation.via_previous_key` |
| `check rate limit` | `ValidateKey`, as a child of `validate key`. Only when the key's policy sets `RateLimit` and you gave the engine a `RateLimiter` | `keysmith.result` |
| `create key` | `CreateKey`, under your span | `keysmith.result` |
| `rotate key` | `RotateKey`, under your span | `keysmith.result`, `keysmith.rotation.reason`, `keysmith.rotation.grace_seconds` |
| `revoke key` | `RevokeKey`, under your span | `keysmith.result`, `keysmith.rotation.grace_windows_closed` |
| `suspend key` | `SuspendKey`, under your span | `keysmith.result` |
| `reactivate key` | `ReactivateKey`, under your span | `keysmith.result` |
| `expire keys` | `CleanupExpiredKeys`, as a root span | `keysmith.keys.expired`, `keysmith.keys.failed` |

These are the values the enum attributes can take:

| Attribute | On | Values |
| --- | --- | --- |
| `keysmith.result` | `validate key` | `ok`, `invalid`, `inactive`, `expired`, `rate_limited`, `error` |
| `keysmith.result` | `check rate limit` | `allowed`, `denied`, `error` |
| `keysmith.result` | `create key`, `rotate key`, `revoke key`, `suspend key`, `reactivate key` | `ok`, `not_found`, `rejected`, `conflict`, `error` |
| `keysmith.rotation.reason` | `rotate key` | `scheduled`, `manual`, `compromise`, `policy`, or `other` for any reason outside those four |
| `keysmith.validation.via_previous_key` | `validate key` | `true` when the caller presented a rotated key inside its grace window, `false` otherwise |

A refused key, a refused state change, a missing key and a lost race are answers, so they leave the span's status alone. Only `error` sets an error status. The status description and `error.type` name the Go type of the innermost error (`*pgconn.PgError`, `context.DeadlineExceeded`), and an `exception` event carries that type as `exception.type` and nothing else. The error's text never goes on a span, because a store's message can quote the values it was given.

A lifecycle hook that returns an error doesn't fail the operation that fired it. It leaves a `hook failed` event on that operation's span, with `keysmith.hook.event` (the values are listed under `keysmith_hook_errors_total` below) and `exception.type`.

`CleanupExpiredKeys` is meant to run on a schedule you own. Each run that finds expired keys, or fails to list them, is one root span back-dated to the start of the run. If your context carries a span (a scheduler's job span, say), it becomes a link and not the parent, so a run started from a long-lived context never hangs off an old trace. A run that finds nothing starts no span.

`ValidateKey` writes the key's last-used time in a goroutine nobody waits for. Its query span is a child of `validate key` that ends after its parent has.

No span carries a raw key, a hash, a hint, a key, policy or rotation ID, a tenant or app ID, or anything a caller typed: names, descriptions, metadata, revoke reasons and `WithRotatedBy` subjects all stay off.

## Metrics

The names below are what you scrape from a Forge app, with forge's `forge_` namespace in front. With your own sink outside Forge, they're recorded without it (`keysmith_key_validations_total`).

| Scraped name | Type | Labels |
| --- | --- | --- |
| `forge_keysmith_key_validations_total` | counter | `result`, `via_previous_key` |
| `forge_keysmith_key_validation_duration_seconds` | histogram | `result` |
| `forge_keysmith_key_operations_total` | counter | `operation`, `result` |
| `forge_keysmith_rate_limit_checks_total` | counter | `result` |
| `forge_keysmith_hook_errors_total` | counter | `event` |
| `forge_keysmith_last_used_updates_failed_total` | counter | none |

| Metric | Label | Values |
| --- | --- | --- |
| validations, validation duration | `result` | `ok`, `invalid`, `inactive`, `expired`, `rate_limited`, `error` |
| validations | `via_previous_key` | `true`, `false` |
| key operations | `operation` | `create`, `rotate`, `revoke`, `suspend`, `reactivate`, `expire` |
| key operations | `result` | `ok`, `not_found`, `rejected`, `conflict`, `error` |
| rate limit checks | `result` | `allowed`, `denied`, `error` |
| hook errors | `event` | `key_created`, `key_create_failed`, `key_validated`, `key_validation_failed`, `key_rotated`, `key_revoked`, `key_suspended`, `key_reactivated`, `key_expired`, `key_rate_limited`, `policy_created`, `policy_updated`, `policy_deleted` |

The validation histogram's buckets run from 0.5 ms to 2.5 s: 0.0005, 0.001, 0.0025, 0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1 and 2.5 seconds.

A few of the values need a word:

- A validation's `error` is a failure on keysmith's side: the store failed while looking the key up or reading its policy, or the hasher failed. When the lookup fails, the caller still gets `ErrInvalidKey`, as it always has. The metric is where a database outage stops looking like a run of bad keys.
- `rate_limited` covers both a limiter that said no and a limiter that failed, because both deny the request. `forge_keysmith_rate_limit_checks_total` tells them apart.
- `expire` counts keys keysmith moved to the expired state, both the ones `ValidateKey` catches past their expiry and the ones `CleanupExpiredKeys` sweeps up.
- `not_found` means the key, its policy or a scope it asked for doesn't exist. `rejected` is `ErrInvalidStateTransition`, `ErrKeyLifetimeExceeded` or `ErrScopeNotAllowed`. `conflict` is `ErrKeyConflict`, a write that lost a race.
- The engine throws hook errors and failed last-used writes away, so these two counters are the only place you'll see them. When one hook fails, the hooks registered after it don't run for that event, and the counter goes up once.

Some queries to start from:

```text
# Share of validations that failed on keysmith's side
sum(rate(forge_keysmith_key_validations_total{result="error"}[5m]))
  / sum(rate(forge_keysmith_key_validations_total[5m]))

# p99 validation latency
histogram_quantile(0.99,
  sum by (le) (rate(forge_keysmith_key_validation_duration_seconds_bucket[5m])))

# Clients still on a key you rotated
sum(rate(forge_keysmith_key_validations_total{via_previous_key="true"}[1h]))

# A rate limiter that is failing, not limiting
sum(rate(forge_keysmith_rate_limit_checks_total{result="error"}[5m]))
```

## The lifecycle counters plugin

The `observability` package is an older, separate plugin. It counts lifecycle events as go-utils counters with no labels, one per event. The engine's own metrics above cover the same events with labels, so most apps don't need it.

```go
import "github.com/xraph/keysmith/observability"

eng, _ := keysmith.NewEngine(
    keysmith.WithStore(store),
    keysmith.WithExtension(observability.NewMetricsExtensionWithFactory(factory)),
)
```

`NewMetricsExtension()` records on a collector of its own, which nothing in a Forge app scrapes. If you want these counters on `/_/metrics`, pass `app.Metrics()` to `NewMetricsExtensionWithFactory`.

| Counter | Incremented when |
| ------- | ---------------- |
| `keysmith.key.created` | Key successfully created |
| `keysmith.key.create_failed` | Key creation fails |
| `keysmith.key.validated` | Key passes validation |
| `keysmith.key.validation_failed` | Key validation fails |
| `keysmith.key.rotated` | Key is rotated |
| `keysmith.key.revoked` | Key is permanently revoked |
| `keysmith.key.suspended` | Key is temporarily suspended |
| `keysmith.key.reactivated` | Suspended key is reactivated |
| `keysmith.key.expired` | Key found expired during validation |
| `keysmith.key.rate_limited` | Key exceeds rate limit |
| `keysmith.policy.created` | Policy created |
| `keysmith.policy.updated` | Policy updated |
| `keysmith.policy.deleted` | Policy deleted |
