The key subsystem is the core of Keysmith. It handles the full lifecycle of API keys from creation through revocation.

## Creating keys

```go
result, err := eng.CreateKey(ctx, &keysmith.CreateKeyInput{
    Name:        "Production Key",
    Prefix:      "sk",
    Environment: key.EnvLive,
    Scopes:      []string{"read:users", "write:users"}, // must already exist
})
```

Every scope you list has to exist in the tenant first (`eng.CreateScope`), or `CreateKey` fails with "scope not found".

The `CreateKeyInput` struct accepts:

| Field | Type | Description |
| ----- | ---- | ----------- |
| `Name` | `string` | Human-readable key name |
| `Prefix` | `string` | Key prefix. There's no default: an empty prefix gives a key starting with `_` |
| `Environment` | `key.Environment` | `key.EnvLive`, `key.EnvTest` or `key.EnvStaging` |
| `Scopes` | `[]string` | Permission scopes to assign |
| `PolicyID` | `*id.PolicyID` | Optional policy to attach |
| `ExpiresAt` | `*time.Time` | Optional expiration time (capped by the policy's `MaxKeyLifetime`) |
| `Description`, `Metadata`, `CreatedBy`, `TenantID` | | Optional; the tenant normally comes from the context |

The result contains the raw key (shown once) and the key metadata:

```go
fmt.Println(result.RawKey)  // sk_live_a3f8b2c9e1d4...
fmt.Println(result.Key.ID)  // akey_01h2xce...
```

## Validating keys

```go
vr, err := eng.ValidateKey(ctx, rawKey)
if err != nil {
    // ErrInvalidKey, ErrKeyInactive, ErrKeyExpired, ErrRateLimited
}

fmt.Println(vr.Key.ID)       // akey_01h2xce...
fmt.Println(vr.Key.TenantID) // tenant-1
fmt.Println(vr.Key.State)    // active
fmt.Println(vr.Scopes)       // [read:users write:users]
```

Validation performs these checks in order:

1. Hash the raw key with SHA-256
2. Look up the hash in the store, then among rotated keys still inside their grace window (`ErrInvalidKey` if neither matches)
3. Check key state: it must be `active` (`ErrKeyInactive` otherwise)
4. Check expiration (`ErrKeyExpired`)
5. Enforce the attached policy's rate limit, if a `RateLimiter` is configured (`ErrRateLimited`). No other policy field is checked here
6. Load the key's scopes
7. Fire `KeyValidated` or `KeyValidationFailed` hooks

Validation doesn't record usage. Call `eng.RecordUsage` yourself if you want it.

## Rotating keys

```go
newResult, err := eng.RotateKey(ctx,
    keyID,
    rotation.ReasonScheduled,
    keysmith.WithGrace(24*time.Hour), // optional
)
```

During rotation:
- A new raw key is generated and returned. The key keeps its ID and state (`active`); only its hash and hint change
- A rotation record keeps the old hash, so the old raw key validates (with `ViaPreviousKey` set) until the grace window closes
- After the grace window, only the new raw key validates
- Without `WithGrace`, the grace period is the policy's `GracePeriod`, else 24 hours

## Revoking keys

```go
err := eng.RevokeKey(ctx, keyID, "compromised")
```

Revocation is permanent. The key state transitions to `revoked` and can never be used again.

## Suspending and reactivating keys

```go
// Suspend
err := eng.SuspendKey(ctx, keyID)

// Reactivate
err := eng.ReactivateKey(ctx, keyID)
```

Suspension is temporary. A suspended key fails validation with `ErrKeyInactive` (the same error a revoked key gets) and can be reactivated later. A revoked key can't be reactivated: `ReactivateKey` returns `ErrInvalidStateTransition`.

## Listing keys

```go
keys, err := eng.ListKeys(ctx, &key.ListFilter{
    State:       key.StateActive,
    Environment: key.EnvLive,
    Limit:       50,
    Offset:      0,
})
```

## Key store interface

The `key.Store` interface defines the storage contract:

```go
type Store interface {
    Create(ctx context.Context, key *Key) error
    Get(ctx context.Context, keyID id.KeyID) (*Key, error)
    GetByHash(ctx context.Context, hash string) (*Key, error)
    GetByPrefix(ctx context.Context, prefix, hint string) (*Key, error)
    Update(ctx context.Context, key *Key) error
    UpdateIfVersion(ctx context.Context, key *Key, version int64) error
    UpdateState(ctx context.Context, keyID id.KeyID, state State) error
    UpdateLastUsed(ctx context.Context, keyID id.KeyID, at time.Time) error
    Delete(ctx context.Context, keyID id.KeyID) error
    List(ctx context.Context, filter *ListFilter) ([]*Key, error)
    Count(ctx context.Context, filter *ListFilter) (int64, error)
    ListExpired(ctx context.Context, before time.Time) ([]*Key, error)
    ListByPolicy(ctx context.Context, policyID id.PolicyID) ([]*Key, error)
    DeleteByTenant(ctx context.Context, tenantID string) error
}
```

Every key carries a `Version` that counts writes to its row. It starts at 0. `Update` and `UpdateState` add one, and `UpdateLastUsed` doesn't, because it runs on every validation and would make every checked write on a busy key a conflict. `UpdateIfVersion` writes the row only when the stored version still matches the one you pass, then stores `version+1` and sets it on your key. If the key is there at another version you get `store.ErrKeyConflict` and nothing changes; a missing key is `store.ErrKeyNotFound`.

The engine's rotate, revoke, suspend and reactivate all write through `UpdateIfVersion` with the version they read, so a rotation racing a revoke can't put the old row back. `Update` stays last-writer-wins on purpose. Code that writes keys straight into the store and never reads a version keeps working.
